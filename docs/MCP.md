# Security MCP

`src/mcp/server.ts`, started via `security mcp` (stdio transport). Built on
`@modelcontextprotocol/sdk@1.30`'s `McpServer.registerTool` high-level API —
verified against the installed SDK's `.d.ts` before writing, not guessed.

The tool surface is intentionally smaller than the PRD's full conceptual
list (`security.recon`, `security.web.scan`, `security.api.scan`, etc.) —
those are exposed indirectly through `security.assessment.run`, which is
what the orchestrator actually implements, rather than stubbing tools that
would just return "not implemented" over MCP.

## Tools

| Tool | Input | Description |
|---|---|---|
| `security.scope.get` | `projectPath` | Reads `.security/scope.yaml`. |
| `security.project.inspect` | `projectPath` | Detected stack + `.security/` configuration status. |
| `security.target.discover` | `projectPath`, `target` | Checks whether a target is in scope, without running any tool. |
| `security.assessment.run` | `projectPath` | Runs the full lifecycle: scope-checked tool execution → correlation → sanitized evidence → report generation. Returns tools run/skipped/errored and the report location. |
| `security.findings.list` | *(none)* | Findings from the most recently generated report. |
| `security.report.generate` | *(none)* | Lists registered projects and their last-assessment timestamps (report *files* are generated by `security.assessment.run`; this tool surfaces registry state, not a re-generation trigger — see limitation below). |

## Known limitation

`security.report.generate`'s name implies it (re)generates a report on
demand; it currently only lists project/registry status because report
generation is tied to `security.assessment.run` completing, not a
standalone action on already-collected findings. Renaming or splitting this
tool is reasonable follow-up work; documented here rather than silently
shipping a misleading name without explanation.

## Scope enforcement

`security.assessment.run` and every tool adapter call
`assertInScope()`/`assertMobileArtifactInScope()` (`src/security/scope-guard.ts`)
before touching a target. A `ScopeViolationError` is surfaced as an error in
the tool's result, not as a crash — the MCP client (the AI agent) sees a
clear "why this wasn't scanned" message.
